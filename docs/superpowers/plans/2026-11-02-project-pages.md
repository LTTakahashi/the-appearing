# Project Pages, Visual Editor and Content Foundation (Phase 2a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four project pages, homepage card links with page transitions, an interactive practice figure, a Sveltia CMS editor at `/admin`, one-file-per-entry content, and a photo-GPS build check, without changing the homepage's visible text.

**Architecture:**
- Content moves from `src/data/*.yaml` to folder collections under `src/content/`, loaded with Astro's `glob()` loader. Folder and file names are the ids, and malformed files already fail the build.
- Project pages are generated by `src/pages/research/[slug].astro` from typed blocks.
- Small pure TS modules (`src/lib/*`) hold logic and are unit-tested via Node's type stripping. Browser behavior is tested with the existing Playwright harness.

**Tech Stack:**
- Astro 7.4.x (`glob` from `astro/loaders`, `z` from `astro/zod`, `image()` in schemas)
- `marked` 18.x
- `exifr` 7.1.x
- Sveltia CMS 0.256.1 (CDN, pinned)
- Existing: node:test, Playwright 1.63.0, axe-core

**Spec:** `docs/superpowers/specs/2026-11-02-project-pages-design.md`. All copy, slugs, orders, simulated data and verdict strings come from it verbatim (§ numbers below refer to it). Phase-1 spec rules still apply.

## Global Constraints

- **Homepage text:** the visible homepage text (hero, cards, rows, news, publications, footer) stays identical to phase 1. Task 1 pins this with a fixture.
- **Slugs:** `arts`, `practice-as-signal`, `smart-homes`, `medication-adherence`, `multi-view`, `sql-component-match`.
- **Pages:** `page: true` only for the first four of those, except `medication-adherence`. Pages exist for `arts`, `practice-as-signal`, `smart-homes` and `multi-view`.
- **Drafts:** `draft: true` entries never appear on any page, route or "Next project" link. Always query through `published()`.
- **Colors:** only tokens from phase-1 §6.1 (`--paper`, `--paper-2`, `--ink`, `--ink-2`, `--muted`, `--rule`, `--rule-strong`, `--accent`), with no hex in components. SVG fills and strokes use the `.fig .i/.is/.a/.as/.p` classes.
- **Sveltia:** pinned at `https://unpkg.com/@sveltia/cms@0.256.1/dist/sveltia-cms.js`. Config keys verified against 0.256.1 types:
  - `backend.auth_methods: [token]`
  - list `types:` (type key `type`)
  - `media_libraries.default.config.transformations.raster_image: { format: webp, quality: 85, width: 2400 }`
- **Build:** the `build` script becomes `node scripts/check-images.mjs && astro build`.
- **Accessibility:**
  - WCAG 2.1 AA in light and dark;
  - no horizontal scroll at 320 px;
  - everything works without JS;
  - motion is off under `prefers-reduced-motion: reduce`.
- **Commits:** every commit ends with the session's two attribution lines.

## Review Focus

1. **Page project missing required fields:** a project with `page: true` but no `minute` (or not exactly 3 items), `question`, `authors` containing `self`, `figure` or `kicker` fails the build naming the file. It must never render a half-empty page (Task 3).
2. **Duplicate block headings:** two text blocks with the same heading would create duplicate ids and a broken "On this page" list. They fail the build (Task 3).
3. **Missing figure image:** a figure block whose `image` file doesn't exist, as when the editor saved it elsewhere, fails the build (Task 4).
4. **Drafts:** a draft project, news item or publication is absent from the homepage, gets no route, and is skipped by "Next project" (Task 1 for lists, Task 3 for routes and next).
5. **Raw HTML or `#`/`##` headings in a text block's Markdown:** HTML is escaped, never executed, and headings are demoted to `h3` so the page outline and rail stay correct (Task 3).
